The backend boundary test proves view + integrations.manage can GET /integrations but receives 403 on /auth/permissions and /auth/brands, correctly under ADR-150. The page uses those two protected admin endpoints for its choices, leaving the permission menu empty. Strict client test reproduces the exact responses and requires a grant choice. A fix may need an accessible integration-management catalogue/brand source; do not weaken the users.manage boundary test. Future endpoint additions may require updating permitted stubs while keeping this behavioral requirement.
