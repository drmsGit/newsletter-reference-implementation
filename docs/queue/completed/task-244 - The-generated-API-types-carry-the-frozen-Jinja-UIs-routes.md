## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
**Found 2026-10-02** while checking why the session that built the deliveries and campaign screens added thousands of lines. Most of them were `frontend/src/api/schema.d.ts`, regenerated by `npm run generate:client` from `/openapi.json` for the first time since 2026-09-20.

**88 of the 198 paths in that file are `/ui/...` routes**: server-rendered Jinja pages and form posts that the React client never calls. They were in the file before that session too, so this is not new, but it is the largest avoidable share of a file every client change regenerates. The cause is that nothing excludes them from the schema. `frontend_router` is included in `backend/main.py:734` with only its guard dependencies. The auth router also serves `/ui/login`, `/ui/users` and `/ui/roles` (see the docstring of `backend/tests/test_jinja_freeze.py:11`), so excluding the frontend router alone would leave those behind. The SPA routes in `main.py` (`:862`, `:867`) and the signed-in docs router (`:885`) already use `include_in_schema=False`, so the pattern is established.

**Why it is worth doing:** the Jinja UI is frozen (`test_jinja_freeze.py` pins its route list). It is not part of the JSON plane that ADR-002 and ADR-170 point 4 describe, and the generated client is supposed to be a picture of that plane. Every `/ui` entry is noise in the types, in `check:contract` diffs, and in `/docs`, where a reader sees HTML form posts listed beside the API.

**What it costs, and why it was queued rather than done:** the `/ui` pages disappear from `/docs` and `/redoc`. Nobody is expected to use those pages from Swagger, but it is a visible change to what ADR-184 exposes. Also check that nothing reads `/ui` paths out of the schema: `test_api_docs.py`, `test_jinja_freeze.py` (which reads `app.routes`, not the schema, but verify that) and any route-inventory test in `test_api_guard.py`. Probably no ADR is needed, because it changes what is documented, not what is served. If the worker disagrees, that is an ADR-184 addendum through the adr-author agent.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Built 2026-10-03. `backend/main.py`: after every include, routes under /ui and every route the frontend router declares are set include_in_schema=False. The rule follows what a route is, not which router declared it, so the auth router's /ui/login, /ui/users and /ui/roles are covered, and so is a router added later. Also removed the JSON GET / root() handler: the frontend router's dashboard is registered first and always won, so it was unreachable while the schema documented it. That's beyond the /ui wording of the ACs, but it serves the task's aim, and nothing referenced it. No ADR or ADR-184 addendum: this changes what is documented, not what is served or who may read the docs. test_jinja_freeze and test_api_docs pass unchanged. `backend/tests/test_schema_excludes_jinja.py`: 3 tests, 3 mutants caught (nothing hidden, frontend router only, /ui prefix only). schema.d.ts: 199 -> 110 paths, 0 /ui; client type-checks, frontend 48 passed; check:contract clean after commit. Suite 1043 passed, rc=0.
