The three shipped roles are a preset, not a model of your org chart (ADR-150 §5) — start from one and change what you need. Permissions are rows, so adding a role never requires code. The permission names stay in code, because each one guards a specific code path.

A user holding several roles gets the union of their permissions: if any one role grants something, they can do it. There is no "deny" permission, so two roles cannot contradict each other. Editing a shipped role makes it yours — it stops being re-synced from the preset when the server restarts.
